# i18n Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `i18next` + `react-i18next` with Korean default / English, persist language in `localStorage`, expose a Select language switcher in the sidebar, and migrate common UI copy (nav, auth, shared filter/search) into JSON resources.

**Architecture:** Initialize i18n once before React render. Store translations under `src/locales/{ko,en}/{common,nav,auth}.json`. Components call `useTranslation`. Route menu labels use `labelKey` instead of hardcoded `label`. LanguageSwitcher is a native `<select>` in `SidebarFooter` so desktop and mobile sheet share one control.

**Tech Stack:** Vite, React 19, TypeScript, i18next, react-i18next, i18next-browser-languagedetector, Vitest, Testing Library, existing Tailwind/Radix UI patterns.

## Global Constraints

- Default and fallback language: `ko`
- Supported languages: `ko`, `en`
- Persist with detector key `i18nextLng` in `localStorage`
- LanguageSwitcher UI: native `<select>` (no new shadcn Select file in this plan)
- Place switcher in AppBar `SidebarFooter` (works for collapsed/mobile sheet)
- Phase 1 scope only: common, nav, auth + PostingFilter / list-toolbar fixed strings + PageLayout home aria
- Do not translate post body content or API error payloads in this plan
- Prefer existing UI patterns; keep commits focused and frequent
- Spec: `docs/superpowers/specs/2026-08-21-i18n-setup-design.md`

- [ ] **Step 4: Create i18n init module**

`src/i18n/index.ts`:

```ts
import i18n from 'i18next';
import LanguageDetector from 'i18next-browser-languagedetector';
import { initReactI18next } from 'react-i18next';

import enAuth from '@/locales/en/auth.json';
import enCommon from '@/locales/en/common.json';
import enNav from '@/locales/en/nav.json';
import koAuth from '@/locales/ko/auth.json';
import koCommon from '@/locales/ko/common.json';
import koNav from '@/locales/ko/nav.json';

void i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources: {
      ko: { common: koCommon, nav: koNav, auth: koAuth },
      en: { common: enCommon, nav: enNav, auth: enAuth },
    },
    fallbackLng: 'ko',
    supportedLngs: ['ko', 'en'],
    defaultNS: 'common',
    ns: ['common', 'nav', 'auth'],
    interpolation: { escapeValue: false },
    detection: {
      order: ['localStorage'],
      caches: ['localStorage'],
      lookupLocalStorage: 'i18nextLng',
    },
  });

export default i18n;
```

- [ ] **Step 4: Implement LanguageSwitcher**

`src/components/layout/LanguageSwitcher.tsx`:

```tsx
import { useTranslation } from 'react-i18next';

const LanguageSwitcher = () => {
  const { t, i18n } = useTranslation('nav');
  const value = i18n.resolvedLanguage === 'en' ? 'en' : 'ko';

  return (
    <label className="flex flex-col gap-1.5 text-sm">
      <span className="text-muted-foreground">{t('language')}</span>
      <select
        aria-label={t('language')}
        value={value}
        onChange={(event) => {
          void i18n.changeLanguage(event.target.value);
        }}
        className="border-input bg-background focus-visible:border-ring focus-visible:ring-ring/50 h-9 w-full rounded-xl border px-3 text-sm outline-none focus-visible:ring-2"
      >
        <option value="ko">한국어</option>
        <option value="en">English</option>
      </select>
    </label>
  );
};

export default LanguageSwitcher;
```

Option labels stay language-native (do not translate).
